# AirNet 功能清单

> 每个功能都带**验收口径**，避免"做完了但说不清对不对"。
> 状态：✅ 原型已实现 ｜ 🟡 部分实现 ｜ ⬜ 未实现

---

## 0. 定位与用户故事

**一句话**：点一下，三秒后告诉你网络好不好、问题在路由器还是运营商、以及能做什么。

| 用户 | 场景 | 他要的答案 |
| --- | --- | --- |
| 普通家庭 | 视频卡顿、游戏掉线 | 是 Wi-Fi 还是宽带的问题？怎么改最省事？ |
| 远程办公 | 会议断续 | 现在这条链路能不能开高清会议？ |
| 半专业人士 | 刚换了路由器/宽带 | 换完之后到底变好没有？给个可对比的数字 |
| IT 支持 | 帮人看问题 | 一份能截图的报告 |

## P0 —— 首发必须（决定了产品是否"能用"）

### F1 一键检测 ✅

- **行为**：点击"开始检测"（或 Ctrl+R），2–3 秒内完成一轮：接口 → 网关 → 参考主机 → DNS；带宽测速保持独立动作。
- **反馈**：工具条显示当前探针与计时并推进进度条，检测期间整页降透明（表示旧数据），按钮转"停止"，可随时取消。
- **验收**：① 15 个 ICMP + 10 次 TCP 握手全部发出；② 取消后 1 个探测周期内停止发包；③ 失败（无网络）给出可读原因而非异常栈。
- **M2 更新**：`MeasurementRunner` 通过 `IProgress<ScanProgress>` 上报六段阶段；进度条向目标缓动，不随阶段跳变。

### F2 健康分与结论 ✅

- **行为**：0–100 分 + 四档（优秀/良好/一般/较差）+ 一句话结论。
- **验收**：① 分档边界 90/75/60 正确；② 丢包 ≥2% 时不得评为"优秀"；③ 一句话结论必须包含"问题域"（有线/无线/对端）。

### F3 关键指标 ✅

- **行为**：延迟（均值 + P95）、抖动、丢包（收到/发出）、下载/上行带宽。
- **验收**：① P95 用最近 60 个样本；② 抖动定义写进 UI 提示（相邻包差值的均值）；③ 每个数字带单位与口径注释。
- **M1 更新**：抖动与 P95 改由 `Stopwatch` 计时的 TCP 握手序列计算（本机 2.6ms，此前恒为 0）；丢包仍由 ICMP 给出，UI 上标注计时来源。

### F4 延迟时间线 ✅

- **行为**：60 秒窗口的实时曲线，带均值虚线、峰值、采样数。
- **验收**：① 采样到显示 ≤ 300ms；② 曲线在 60 点处滚动而非无限增长；③ 丢包点要在曲线上有断口（M1）。

### F5 诊断结论与建议 ✅

- **行为**：按影响排序的问题列表，每条 = 严重度点 + 标题 + 一句解释 +（可选）动作按钮。
- **已实现规则**：丢包三档、抖动两档、无线信号偏弱（含 dBm）、DNS 解析耗时、首包/TLS 偏慢、**ICMP 被拦截的透明说明**。
- **验收**：① 最多展示 3 条，其余折叠；② "正常"也要有一条（绿色），否则用户会以为没测到；③ 每条建议必须可执行或可验证。
- **M1 更新**：按严重度排序并截断到 4 条；DNS 那条会带上完整首包拆解（`首包共 106 ms：TCP 12 · TLS 38 · 等待 47`）。
- **动作按钮**：已接命令。"排查链路"跳到链路路径页，其余（优化 DNS / 优化信号 / 查看建议）跳到设置页；真实的 DNS 执行仍需用户在设置页确认。

### F6 带宽测速 🟡

- **行为**：下行/上行环形仪表 + 结果明细 + 近 6 次真实下行趋势。
- **验收**：① 结果标注"单流/多流"口径；② 12MB 样本；③ 未测速显示"未测速"，不写 0 或样例值；④ 测速结果写入历史供趋势使用。
- **缺口**：原型只跑单流下行，上行显示"未测速"；上行与多流仍未做。

### F7 链路概览 ✅

- **行为**：本机 → 网关 → 参考主机的逐段耗时条 + 出口 IP + **首包四段分解条**（DNS / TCP / TLS / 等待）。
- **验收**：① 网关不可 ping 时不显示 0ms 而显示"超时"；② 出口 IP 被拦截时显示"未获取"，不阻塞扫描；③ 四段之和等于显示的总首包时间。
- **M1 更新**：首包分解已接入，段宽按耗时占比绘制，图例给出四段毫秒数。
- **M2 更新**：出口 IP 走 Cloudflare / 3322 并行 best-effort；隐私开关仍待 M3。

### F8 历史与对比 🟡

- **行为**：最近检测列表（首页 3–5 条 + 历史页全量），点进去看那一轮的完整快照。
- **M1 更新**：JSONL 落盘（30 天 / 500 条 / 裁剪安全）、首页自动切换为"本机实测"、设置页显示条数并可清空。
- **验收**：① 保留 30 天；② 两次检测可对比差值（+12 Mbps / −4ms 用 ↑↓ 标注）。
- **缺口**：还没有独立的"历史页"与两次快照的差值对比（M3）。

### F9 设置 ✅

- **行为**：主题（跟随系统/浅/深）、定时自动刷新、双探测开关、保留历史、清空数据。
- **验收**：① 改动即时生效且本地持久化；② 清空历史需二次确认。
- **M1 更新**：清空历史已接真实 Store；显示记录条数与"保留 30 天"。
- **M2 更新**：主题、自动刷新、双探测、保留历史都写入 `settings.json`；自动刷新 60s 一次，
  窗口最小化/不可见时跳过；双探测关闭后只跑 ICMP；保留历史关闭后不再追加记录。
- **不做的**：主扫描不包含 12MB 带宽测速，"检测时包含带宽"这个开关已移除，测速保持独立动作。

### F10 报告导出 ✅

- **行为**：一键生成自包含 HTML（含曲线与结论），浏览器直接打印为 PDF。
- **验收**：① 单文件、离线可看、无脚本；② 默认掩码内网 IP；③ 文件名含时间。
- **M2 更新**：`ReportBuilder` 输出 7–8KB，内联 SVG 曲线；工具栏「导出报告」走系统保存对话框，CLI 用 `--report <path>`；CI 对报告结构做断言。

## P1 —— 差异化（决定"比同类好在哪"）

| 编号 | 功能 | 行为 | 验收 |
| --- | --- | --- | --- |
| F11 | **三段归因** ✅ | 局域网/运营商/对端三段增量，直接指出"哪一段坏了" | M2 完成：粗定位（扫描后）+ 逐跳定位（追踪后）两级；健康链路不报警 |
| F12 | **逐跳链路** ✅ | 16 跳内每跳耗时，标出突变点 | M2 完成：系统 traceroute，解析与本地化提示无关；实测 14 跳 / 17s；目标未响应时不判"对端" |
| F13 | **Wi-Fi 体检** 🟡 | 信号强度、协商速率、PHY 代际（wlanapi）；邻区与信道建议 | **2026-11-12 真机验证**：SSID / 信号质量 / 速率 / PHY 均可用；dBm 为估算；邻区扫描与信道建议仍待做 |
| F14 | **DNS 对比** | 本机 DNS vs 223.5.5.5 vs 1.1.1.1 解析同一域名的耗时 | 结果差异 >5ms 才建议切换（避免噪音） |
| F15 | **一键优化 + 还原** 🟡 | DNS 切换（Windows 提权，UAC 可取消），应用前记录原值，一键还原 | M2 完成窗口版：命令先展示可复制，还原记录落到 `dns-backup.json`；macOS/Linux 仅生成命令 |
| F16 | **IPv4/IPv6 双栈** | 分别测两条路，指出"IPv6 更差"这类常见坑 | 无 IPv6 时不影响总评 |
| F17 | **自动复测** ✅ | 60s 周期采样，只在窗口可见时；当前快照随之更新 | 最小化/隐藏即暂停；CPU 占用尚未实测 |
| F18 | **命令行模式** | `airnet --probe --json`，供脚本/CI 用 | 输出稳定 JSON schema；退出码区分 健康/降级/失败 |
| F19 | **快捷键** ✅ | Ctrl+R 检测、Ctrl+1..6 页面、Ctrl+T 主题、Esc 停止 | 全窗口生效；焦点在输入框时不抢占 |
| F26 | **网站延迟** ✅ | 11 个默认站 + 最多 8 个自定义站；四段/3 次中位数；HTTP 状态识别；`--sites` CLI | 自定义落 `sites.json`，历史落 `sites.jsonl`；403/5xx 单独标记；不并入健康分 |

## 明确不做

| 不做 | 原因 |
| --- | --- |
| "网络加速" | 无法在不改路由的前提下承诺收益，做了就是营销话术 |
| 后台常驻监控 | 与"轻"冲突；需要监控的用户应该用专门工具 |
| 驱动级抓包 | 需要签名驱动，破坏"无驱动"承诺，且杀软误报 |
| 上传测量数据 | 隐私风险极高（IP、SSID、内网拓扑） |
| 自动改 hosts / 代理 / 防火墙 | 破坏性大、难回滚 |

## 优先级依据

1. **先能判断好坏**（F1–F5）：没有结论的仪表盘只是玩具。
2. **再能定位**（F11–F13）：同类产品普遍止步于"分数"，归因才是差异点。
3. **最后能修**（F15）：改配置是唯一"真的优化了"的动作，但必须可回滚。
4. 报告与趋势（F10/F23）放在后面：它们是留存功能，不是首次体验功能。
